# Firestore collections (data dictionary)

Firestore stores **collections** of **documents**. A collection plays the role of a table, a document is a row, and the **document ID is the primary key**. Foreign keys are fields that hold another document's ID.

Project: `harvest-printing-centre` (Firebase). Authentication (email and Google users) is held by Firebase Authentication, not in Firestore.

## orders (created by the mobile app through the API)
| Field | Type | Key | Meaning |
|---|---|---|---|
| (document ID) | string | Primary key | Generated by Firestore (`seed-order-01` ... for sample data) |
| userId | string | Foreign key | Firebase Authentication uid of the customer |
| items | array of maps | | One map per line: `serviceId`, `name`, `quantity`, `unitPrice` |
| items[].serviceId | string | Foreign key | `services` document ID |
| total | number | | Sum of `unitPrice` x `quantity` for priced lines, in rand |
| requiresQuote | boolean | | `true` if any line has no price (quote only) |
| status | string | | Pending, Confirmed or Completed |
| createdAt | timestamp | | Set by the server |
| source | string | | `seed` on sample documents only |

Prices are copied from `services` by the API when the order is placed. The app never sends prices.

## Relationships
- `bookings.serviceId` → `services` (many bookings per service)
- `portfolio.serviceId` → `services` (many portfolio items per service)
- `orders.items[].serviceId` → `services` (many order lines per service)
- `orders.userId` and `bookings.userId` → Firebase Authentication user (not stored in Firestore)

Seeded sample documents carry `source: "seed"` so they can be told apart from real customers and deleted before the real launch. Sample orders are loaded with `database/seed-orders.js`.

## Access rules
See `firestore.rules`. Visitors can create bookings and contacts, but only the admin Google accounts can read them. `services` and `portfolio` are public read-only. `orders` has no browser access at all: it is read and written only by the API (Firebase Admin SDK, which bypasses these rules).

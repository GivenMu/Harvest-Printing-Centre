# Firestore collections (data dictionary)

Firestore stores **collections** of **documents**. A collection plays the role of a table, a document is a row, and the **document ID is the primary key**. Foreign keys are fields that hold another document's ID.

Project: `harvest-printing-centre` (Firebase). Authentication (email and Google users) is held by Firebase Authentication, not in Firestore.

## services (14 documents)
| Field | Type | Key | Meaning |
|---|---|---|---|
| (document ID) | string | Primary key | Slug such as `business-cards` |
| name | string | | Display name |
| category | string | | Business Printing, Branded Clothing, Signage, Packaging, Event Printing, Promotional Displays |
| description | string | | What the service is |
| price | number or null | | Starting price in rand (null = quote only) |
| priceLabel | string or null | | Text shown on the site, e.g. `R300 for 100` |
| imageFile | string | | File name in `website/images/` |
| sortOrder | number | | Display order |

## Relationships
- `bookings.serviceId` → `services` (many bookings per service)
- `portfolio.serviceId` → `services` (many portfolio items per service)

Seeded sample documents carry `source: "seed"` so they can be told apart from real customers and deleted before the real launch. The mobile app will add its own collections (for example orders); add them here when they exist.

## Access rules
See `firestore.rules`. Visitors can create bookings and contacts, but only the admin Google accounts can read them. `services` and `portfolio` are public read-only.
